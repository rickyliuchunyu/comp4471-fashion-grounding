# 团队协作与启动清单

团队有三人，负责人尚未分配。先共同理解 [项目讲解](project_guide.md)，再核对 [技术设计](technical_design.md)、[数据协议](data_protocol.md) 与 [接口规范](implementation_spec.md)，根据兴趣、时间和依赖决定分工。本文不将任务分配给指定成员。

## 如何阅读和修改仓库

仓库先公开，任何人可读取；修改仍需要仓库写入权限。两位队友的 GitHub 用户名确定后再添加协作者。阅读公开仓库不需要邀请。

```sh
git clone https://github.com/rickyliuchunyu/comp4471-fashion-grounding.git
cd comp4471-fashion-grounding
git switch -c docs/clarify-scope
```

上述分支名只是一次文档修改示例。首次阅读无需安装模型依赖。当前没有训练入口，不能把这些命令理解成已具备模型运行环境。

通常从 main 新建短分支，在一个分支中处理一项明确改动；提交后创建 Pull Request，说明改了什么、怎样检查、是否影响数据接口或实验结果。合并前由另一名成员阅读。不要把私有访问令牌写入文件或共享 GPU 终端历史。

## 先约定数据与模块接口

接口目前是拟定格式，示例文件都带有人工示例标记。详细类型、384/1024/12 维张量、padding、缓存和错误状态见 [接口规范](implementation_spec.md)；实现前共同审查，修改同步更新文档与调用方。

| 接口 | 约定内容 |
| --- | --- |
| 处理后的实例数据 | 源数据集、源图片 ID、图片尺寸、目标类别 ID、实例 ID、框、分割标注、映射版本 |
| 查询标注 | 图片 ID、完整文字、语言、目标实例 ID、查询类型、划分、复核状态 |
| 分割候选 | 图片 ID、候选实例 ID、类别、分割置信度、框、mask 与图像尺寸 |
| 语言选择 | 完整查询与候选集合，输出选中候选 ID、排序分数与状态 |
| 最终预测 | 选中类别、框、mask、运行版本；失败时保留明确状态 |

框统一采用像素坐标 `[x_min, y_min, x_max, y_max]`，原点在左上，x 向右、y 向下，右下边界为排他边界。与 COCO 的 `[x, y, width, height]` 转换必须显式处理。mask 保持与输入图片像素对齐，不能混用缩放后的坐标。

项目类别 ID 为 1–8；框架如需连续的 0–7 训练标签，应单独做映射，预测导出时还原为项目 ID。COCO instance ID 与推理 candidate ID 不混用。示例见 [query_record.json](../examples/query_record.json) 和 [prediction.json](../examples/prediction.json)。

## GPU 平台建议

建议 AutoDL 普通容器实例、单张 RTX 3090 24GB、按量计费。尚未开通实例，尚未承诺具体训练预算；先在小规模检查中测量显存和耗时，再讨论正式实验预算。三人在本地通过 GitHub 同步，GPU 正式实验登记后排队运行。

建立实例后要完成以下启动检查：

1. 确认官方数据访问方式、模型权重来源及下载可用性。
2. 锁定 Python、PyTorch、CUDA、Detectron2 和 Mask2Former 所需依赖；记录 GPU 与驱动版本。
3. 成功加载若干八类样本，显示掩膜并检查类别和坐标。
4. 跑通小批量训练、权重保存和恢复、单图预测与指标计算。
5. 测量冻结编码器和匹配模块的显存；必要时分阶段加载、预先缓存区域特征。
6. 检查一次完整的图片与文字输入到目标叠图流程。

只有这些检查通过，才添加精确的安装和训练命令。不能先把任意最新依赖拼成“已验证环境”。

AutoDL 按实例开机时间计费，结束训练进程不会停止实例计费；按量实例关机结束计算资源计费，扩容磁盘等可能另外计费。价格和库存以租用时平台显示为准。训练结束备份代码版本、数据清单、权重、日志和指标，关机与数据保留按官方规则执行。

官方参考：[快速开始](https://www.autodl.com/docs/quick_start/)、[计费说明](https://www.autodl.com/docs/price/)、[环境与存储](https://www.autodl.com/docs/env/)。

## 数据与结果如何共享

GitHub 保存代码、配置、说明、划分清单的索引与小型指标文件。原始数据、处理数据、权重和大批输出存放在团队确定的共享存储，不直接提交 GitHub。下载来源、许可要求、清单哈希和存储位置需要有记录；目前共享存储尚未确定。

每个正式实验在 [registry.csv](../experiments/registry.csv) 登记，S1–S4、L1–L5 是系列计划，不是一行代表全部运行。执行时按条件和种子新建唯一 ID，例如 `S1-FP-seed42`、`L2-oracle-seed43`，填写实际配置及结果，保留系列计划行。

- 开始前：负责人、代码提交、配置、数据清单哈希、种子、初始化权重、唯一输出目录。
- 结束后：完整日志、实际指标、运行时间、可视化与状态；失败也记录。
- 复核时：另一名成员检查划分、运行配置、指标计算与证据链接。

表中的 mask AP 只适用于分割评估；语言实验填写选择准确率与目标 mask IoU；其他指标写在运行指标文件中。空白表示尚未记录或不适用，不代表零。图像缓存要关联编码器版本、预处理与 mask 来源，改变任一项就重新生成缓存。
