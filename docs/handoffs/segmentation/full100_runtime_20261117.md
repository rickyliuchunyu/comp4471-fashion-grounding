## 固定训练和评价行为

沿用[已准备配方](full_fashionpedia_100ep_preparation_20261117.md)：官方 COCO 权重重新初始化 R50 八类模型，seed42，768 输入、scale0.5–2.0、水平翻转，microbatch2 × accumulation8，AdamW LR1e-4 / backbone0.1 / decay0.05，warmup500，AMP 与 clip0.01。现有 AMP 有限重放策略保留：每 update 最多4次重试、全程最多16次溢出；超出即停，不能自动放宽。

真实 N 由已冻结且接受的训练元数据确定：`u(e)=ceil(e*N/16)`。连续 shuffle sampler 不在每个 epoch 补齐数据；80/90 epoch 后降 LR，100 epoch 停止，最多多消费15张取整曝光。没有继承旧20k或3小时总上限，也没有无限追加 epoch。现有2图 microbatch 累积不宣称在所有原生损失归一化上等价于单次16图前向。

dev 固定 250 图/1008 GT v1、FP32、800/1333、原生 instance top100。报告 AP/AP50/AP75、small/medium/large 和逐类 AP；AR100 保留在原 COCO `coco_summary.txt`，尚无新增独立 JSON AR100 字段。Boundary AP、train-only 256图诊断和独立确认集仍是准备计划中的后续项，不包含在此次执行接线内，不冒称已实现。候选阈值及语言查询不参与标准 AP 推理或分割 checkpoint 选择。

每次评价记录 checkpoint、训练/dev、配置、源码和 binding 的身份哈希，保存完整预测。仅完整且无错误、人口一致的报告参与选模；最大 dev mask AP 胜出，同分取更早 update。恢复点为最新完整训练 checkpoint，选模点为最佳 AP checkpoint，分别记录，不能混用。不会自动替换历史候选或语言缓存。

## 冻结与接收 binding 格式

先由生产方按[冻结清单](../../../configs/runs/segmentation/full_fashionpedia_freeze_checklist.json)发布真实材料，再完成受影响输入的增量消费接收；本轮只定义读取格式，没有生成真实批准记录。

binding JSON 要求 `schema_version=1`、`purpose=full100_data_binding`、真实 `train_package`/`dev_package`，以及 `references.freeze / acceptance / dev_report` 三个 `{path, sha256}`。相对引用以**包含该引用的 JSON 目录**为基准；写入最终路径后再算哈希。复制准备清单时须修正其仓库相对 mapping/evidence 路径，不能把旧路径默认为相对新目录仍有效。

| 记录 | 执行器检查的必需内容 |
| --- | --- |
| freeze | `formal_freeze=true`、`status=frozen`、dataset=fashionpedia、source_split=train；真实图数/实例数、manifest/annotation SHA；mapping `{path,sha256}`；受保护 dev/test 身份 |
| source_accounting | `coverage=all_eligible_official_train`，整数 `source_images / retained_images / excluded_images`；source=retained+excluded，retained=实际训练 N；明细由 source_inventory/quality_disposition 证据提供 |
| freeze.checks | 冻结清单全部10个 ID，均 `status=passed`、`evidence={path,sha256}`；consumer_acceptance 绑定本次真实接收 receipt |
| freeze.acknowledgements | wkq/lcy/wyz 各自真实记录的 `{path,sha256}`；记录含 member、decision=approved、reviewer_identity、reviewed_at、该包 manifest/annotation SHA；不可由Codex代签 |
| acceptance | `status=passed`、`scope=full_fashionpedia_segmentation_input`、接收实现40位 `source_commit`；training_data/evaluation_data 各含 manifest/annotation SHA，mapping_sha256、train_images/train_instances/dev_images/dev_instances、`catalog_sha256` |
| acceptance 验证范围 | `image_and_mask_acceptance_complete`、`near_duplicate_review_complete` 为真；`training_id_mapping` 是项目1–8→内部0–7；protected_test_manifest_sha256；overlap.dev/test 的 image_id/source_identity/group_id/sha256 四项均0。布尔结果须由真实接收/复核证据支持，不是自行填真即可取得人工审核 |
| dev_report | 模板已指向原 B20k 完整 dev 报告，复用同一 dev 的真实成功记录；保留原训练身份，不伪装成完整数据新训练结果 |

元数据要求保持 schema3、Fashionpedia 来源/分区、唯一 ID、原图尺寸/路径、来源 ID/group/SHA、现有八类名称与 ID。`annotations_coco.json` 的 mask 必须是原图尺寸压缩 RLE（`counts` 为字符串）；这与现有训练 mapper 一致。其他表示需由生产转换/接收过程规范化并形成新哈希，入口不每次解码重写。训练时才按所取样本正常加载像素和 mask。

完整包接收须结合旧10k已通过证据，只验证新增/变化部分并保留复用范围；不是再次重跑 COCO 下载、旧200-update、旧恢复或模型 smoke。入口元数据校验以已接受且保持不变的发布包为前提，不能代替首次像素/几何接收。test 只读既有隔离证据与 hash，训练不消费 test。

## 执行和恢复方法（本轮未执行 GPU 命令）

在本分支 repo 根目录，已实际执行的默认命令：

```bash

  --output docs/handoffs/segmentation/evidence/full100_runtime_20261117/preparation
```

实际结果：prepared、execution_requested=false、ready_for_training=false。代码源为上述 `ee7db25`，不是完成后文档提交；[标准输出](evidence/full100_runtime_20261117/prepare_stdout.txt)。后续启动应固定自己的最终干净 commit，重新生成真实 contract。

**下面仅为冻结接收和启动授权具备后的用法，本轮未执行。** 使用独立服务器 checkout、实际完整 binding、新 run 目录；原5k/10k未释放GPU时共享锁会拒绝。运行入口前按 AGENTS 核对整组进度、资源并另登记真实 run。

```bash
PYTHONPATH=src /root/autodl-tmp/fashion-grounding/envs/segmentation-v1/bin/python \
  scripts/run_full100.py --binding /absolute/path/to/accepted-full100-binding.json \
  --output /root/autodl-tmp/fashion-grounding/runs/segmentation/segmentation-full100-YYYYMMDD-r01 \
  --execute
```

同一 run 显式恢复：完全相同的命令加 `--resume`；源码 commit、plan/binding/输入/配置哈希必须保持一致，即使只是文档 commit 变动也不能静默恢复。重新签出原 run 固定的独立 checkout 后恢复，不修改当前对照 checkout。

恢复加载 model/optimizer/scheduler/scaler/sampler/RNG/AMP recovery 完整状态，检查哈希、组件 fingerprint 与绝对 update。不重新 warmup，不使用最佳 AP 权重替代最新恢复点。训练中断后从最后完整 epoch checkpoint 继续，未保存的更新会重做；评价失败则先补该点评价，已经完整成功的评价只验证文件/身份，不重推理。

新 attempt 永远写新子目录；损坏或身份冲突的完成缓存会停机，不能当成功结果略过。共享锁覆盖整条训练/评价链；占用 GPU、他人运行记录、活 owner 或剩余磁盘不足均拒绝。仅显式恢复自己的同 contract 且 owner 已死亡、GPU 空闲的遗留记录可标为 interrupted；不终止队友进程。Linux 子进程父死亡保护和正常中断仅清理本次 worker 进程组；本轮未在服务器启动该新 wrapper 验证信号行为。

磁盘预算默认每份完整 checkpoint 768 MiB、最多100份，另留10 GiB（全新约85 GiB）；是执行前估算，不是实测完整数据输出占用。不自动删除旧权重；实际运行前根据现有同模型 checkpoint 大小与数据包占用确认余量。
