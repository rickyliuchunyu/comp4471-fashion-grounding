# 项目讲解：描述指向哪一件服饰？

当前版本为 2026-11-05。本文讲解设计，实际训练、评估与演示代码尚未实现。方法细节见 [技术设计](technical_design.md)，全部实验见 [实验计划](experiment_plan.md)。

## 目的与范围

给定图片和“右边的红色包”等完整描述，输出一个明确目标的 mask、bounding box 和类别。图片里只有一个包时，识别类别就可能成功；有两个相似包时，才需要真正利用外观或位置。我们要知道模型在哪些情况下理解了这些信息，以及错误发生在哪一步。

核心范围是八类整件服饰、单目标、中英文描述，左右均按图片视角。八类是统计分组，描述仍可以使用“钱包”“帽子”等源细类词。部件、多目标、复杂人物关系和开放域无目标拒绝不属于核心承诺。模糊查询先复核，不能强行给一个目标 ID。

## 三个研究问题

1. 已有图文模型直接匹配服饰区域与描述时，哪些查询容易、哪些困难？
2. 少量服饰指代表达监督能否改善外观、同类多实例和自然改写表现？
3. 学习的空间模块是否超过简单方位规则？最终错误中候选漏检与语言选错各占多少？

不继承实习 PRD 的指定技术栈或验收数字。使用公开数据、实现与预训练权重完成新的课程实验，不把实习代码、权重或历史指标作为本次结果。

## 模型分工

| 部分 | 做什么 | 是否训练 |
| --- | --- | --- |
| Mask2Former-R50 | 找到图片中服饰实例，产生候选 mask | 在 Fashionpedia 上微调 |
| SigLIP 2 图像编码器 | 将每个候选裁剪转成图像特征 | 核心实验冻结 |
| SigLIP 2 文本编码器 | 将完整中英文描述转成对齐的文本特征 | 核心实验冻结 |
| 外观残差排序头 M1 | 在原始相似度上学习服饰匹配修正 | 训练小网络 |
| 文本条件空间头 M2 | 根据描述使用位置和同类次序 | 在 M1 基础上新增并训练 |

候选里漏掉目标时，排序器无法恢复它。因此先用 GT 候选检查语言能力，再用固定预测候选评估用户实际得到的结果。GT 候选是诊断条件，演示时不能读取。

原来的 DINOv2 + BGE-M3 保留为可选 X1，不预先判定它一定更差。用已有图文对齐模型作起点，可以将主要监督用于领域适配，是否有效由实验回答。

## 为什么需要这些比较

B0 规则帮助检查类别与位置流程；B1 测试零样本图文表示；B2 给零样本方法加入简单方位规则。M1 检查少量领域学习，M2 检查额外空间学习。尤其要比较 M2 与 B2，避免仅仅因为基线没有坐标而夸大学习模块价值。

E1 使用 SAM 3 或 Grounding DINO + SAM 2 的一个固定版本，比较完整系统。外部系统产生自己的候选，与 B0–M2 的共享候选比较必须分表。不能把两个完整系统的差异归因于某一个模块。

## 数据与人工工作

Fashionpedia 提供 mask 与属性，但我们仍需建立“图片、完整描述、唯一目标”记录。先在训练集试点 100–200 张，审核后选取分割训练约 5,000–10,000 张、语言训练约 800–1,200 张；官方 validation 内另划 dev 约 200–300 张和项目 final test 约 300–500 张。数量是计划范围，不是已完成规模。

先划分再写描述；同图翻译与改写不能跨分区。最终测试由人独立撰写和交叉复核，覆盖类别、外观、空间、组合及超出训练模板的自然改写。保留源细类，单独分析宽泛 accessory 和鞋子导致的统计偏差。详见 [数据协议](data_protocol.md)。

DeepFashion2 只在可选共有五类分割实验中使用。RefCOCO 的“穿红衣服的人”目标通常是人，不能把整个人的 mask 当作红衣服标注；FashionIQ 等检索数据也不直接提供本任务需要的同图实例监督。

## 推进顺序与交付

完整的三人执行顺序、依赖、GPU 排队和阶段验收见 [完整工作流程](workflow.md)。以下是概览。

1. 建立数据试点与冻结划分，利用 GT 裁剪跑 B0/B1/B2；同时检查分割环境。
2. 微调分割器、缓存预测候选及冻结特征，训练 M1/M2。
3. 完成端到端评价、E1、反事实与改写诊断，必要时选择扩展实验。
4. 锁定方案并统一测试，制作失败案例、延迟表、演示和可复现报告。

最终应交付可复核的数据协议与描述集、共享候选上的公平比较、完整系统结果，以及漏检/选错/边界错误的分析。模块没有提升也是可报告的结果，不要求每个想法都成功。三人暂定职责、并行关口与开工任务卡见 [协作说明](team_workflow.md)：lcy 负责分割，wyz（A）负责图文，wkq（B）负责数据/评估；简称已绑定，账号权限仍待分别核验。
