# 可选扩展：研究深度、可靠性与交互演示

本文记录讨论形成的扩展计划。所有新增能力均未实现、未验证；难度是相对于现有候选分割与图文排序方案的增量估计，不是工期承诺。核心任务仍是中英文描述指向单个整件服饰，不因本文自动改为多目标或开放域对话。

主方法、数据协议和评价规则分别见 [技术设计](technical_design.md)、[数据协议](data_protocol.md) 和 [实验计划](experiment_plan.md)。本文补充扩展范围与优先级，不改变核心实验的固定候选、公平对照与测试集隔离原则。

## 1. 推荐组合与实施门槛

建议先完成核心基线与端到端评估，再选择一个研究扩展和一个演示扩展：

- **研究扩展：**优先已有 X3 的背景抑制实验，比较普通裁剪、掩码背景抑制与上下文裁剪。
- **评估特色：**将已有 D1/D2 和中英配对评价整理成统一语言挑战集；不是重复新增一套核心实验。
- **演示扩展：**先做候选与评分可视化，再视预算增加有限范围的一轮交互纠正。
- **备选：**无目标拒绝、同条件多目标、局部编辑、否定理解；无需全部完成。

启动前应具备合法且可缓存的候选输出、可复现的 B1/B2 预测和冻结的数据划分。新增训练、阈值、词表和裁剪设置只用训练集/开发集确定。最终测试前登记选中的扩展、配置与指标；未选中的项目保持规划状态。

| 方向 | 价值 | 增量难度 | 建议位置 |
| --- | --- | --- | --- |
| 背景干扰与区域输入（X3） | 解释 mask 和上下文对匹配的作用 | 低至中 | 优先研究扩展 |
| 语言挑战集（D1/D2 与中英配对） | 检验语义稳定性与变化敏感性 | 低至中，主要是标注复核 | 完善已有评价 |
| 候选与评分可视化 | 支持错误分析和现场展示 | 低 | 优先演示扩展 |
| 一轮交互纠正 | 展示语言如何改变选择 | 中 | 可视化之后选择 |
| 无目标拒绝 | 降低不存在目标时的误选 | 中 | 可靠性备选 |
| 同条件多目标 | 返回所有满足条件的实例 | 中 | 独立任务备选 |
| 掩码驱动的局部编辑 | 展示定位结果的应用 | 低至中 | 演示备选 |
| 否定条件理解 | 分析更复杂的语言组合 | 中至高 | 小规模挑战项 |

X3 复用现有实验编号。交互、拒绝、多目标等仅是设计选项，未填入运行登记表；选定并定义数据与配置后再分配唯一实验 ID。原有 X1/X2/X4/X5 仍保留，研究扩展优先级调整为 X3 → X1 → X2 → X4 → X5，不承诺全部执行。

## 2. X3：背景干扰与区域输入

**研究问题：**服饰匹配主要依赖目标外观，还是受裁剪中的背景、相邻衣物和上下文影响？掩码的价值是否超出最终输出边界？

### 最小实验

先固定冻结的 B1 编码器、查询、候选及几何信息，比较：

| 变体 | 区域输入 | 控制要求 |
| --- | --- | --- |
| A 普通裁剪 | 原图紧致 bounding box | 沿用主基线 |
| B 背景抑制 | 与 A 相同的框，候选 mask 外填固定中性色 | 只改变框内背景，填充值在 dev 阶段登记 |
| C 上下文裁剪 | 扩大 A 的框，保留原图内容 | 固定扩框比例、边界裁切和 processor；不是仅改变背景的纯对照 |

A/B 是核心受控比较；C 为额外上下文条件，会同时改变目标在输入中的相对尺度，应单独解释。三者都使用同 revision 的图像预处理，缓存键记录 mask 来源、填充值与扩框比例。

GT 候选与预测候选分别评价。预测条件只能使用预测 mask，不能用 GT 修正区域输入；候选集合与目标关联保持不变，因此同条件下候选覆盖率不应因裁剪变体变化。

### 指标、产出与停止条件

- 报告选择准确率、端到端目标 IoU/Success@0.5，并按颜色描述、小目标和同类干扰分组；给出图片数与查询数。
- 按现有图片级配对统计规则比较方法，展示成功和失败案例，不根据测试效果重新选填色或扩框比例。
- 最小交付是一张对照表及区域输入示例；不预设去背景一定有利，上下文也可能提供有效信息。
- 若进一步训练 M1/M2，各区域变体必须使用匹配的训练数据、预算与输入策略。仅在测试时改变输入应明确称为输入干预，不能冒充重新适配后的最优性能。
- 若预算不足，完成 A/B 即可，不扩大为背景生成或图像合成项目。

## 3. 语言挑战集：稳定性与正确变化

在已有 D1 左右反事实、D2 自然改写及中英对应查询上统一分组，研究“语义不变时是否稳定，语义改变时是否正确切换”。

| 类型 | 示例 | 预期 |
| --- | --- | --- |
| 中英对应 | “右边的红色包” / “the red bag on the right” | 同一目标 |
| 自然改写 | “最右边的包” / “靠图片右侧的那个包” | 在人工确认语义等价时选同一目标 |
| 空间反事实（D1） | “左边的包” / “右边的包” | 两个描述各自有唯一目标时正确切换 |
| 属性反事实（可选） | “红色包” / “黑色包” | 两个目标均可见且描述唯一时正确切换 |

每组必须人工复核，记录图片 ID、查询 ID、目标 ID、语言、组 ID 和关系类型；字段是拟议扩展，尚未修改现有数据接口。翻译、改写和配对查询随图片进入同一数据分区。图片不足以支持唯一目标的查询不能硬设标签；不存在目标的情况留给独立拒绝实验。

报告单条准确率、两条均正确率/整组全部正确率，并补充同义一致率。输出一致但一起选错不算理解成功；输出发生变化也不代表反事实查询理解正确。测试描述与目标先冻结，再运行模型；按图片采样统计，避免把同图改写当成独立样本夸大样本量。

最小交付：统一组 manifest、分组结果表和成对叠图。属性反事实是可选补充，中英配对与 D1/D2 是已有计划的整理。

## 4. 候选可视化与一轮交互纠正

### 4.1 先完成评分诊断界面

同一界面展示原图、带 ID 的候选 mask、Top-k 候选、最终选择，以及 `s_pretrained`、外观残差、空间项和总分。按实际模型输出展示，不为 B1/B2 伪造学习模块分数。

这些是评分诊断，不是模型完整的因果解释。相似度、sigmoid 值和总分均不直接标为“正确概率”。高亮候选漏检、无候选和不支持的操作；报告纯模型时间与界面显示时间时分别计时。

### 4.2 再选择有限范围的纠正功能

示例：“选中那个包” → 用户看到选择 → “右边那个” → 更新目标。

第一版只支持明确列举的操作：补充左/右条件、补充可见颜色、选择更大/更小候选，或排除上一次选中的候选。保存当前图片、候选 ID、已有查询约束和历史选择；明确更大/更小的参照对象及几何定义。用有限规则解析即可，界面公开支持范围，未知表达返回提示，不声称通用对话理解。

新增条件应与已有条件组合；排除操作至少排除先前候选 ID，重复分割候选仍可能指向同一个真实物体，应作为失败类型记录。无法保持唯一解释时请求澄清或报告不支持，不静默改写用户意图。

评估采用单独复核的两轮查询集，固定目标与可用纠正类型，不向推理模块提供 GT ID。可用人类按固定规则提供反馈，并计入交互成本；若采用 GT 驱动的模拟反馈，必须标注为模拟协议，不能等同真实用户实验。

报告全部会话的纠正前/后一轮准确率、首次失败子集恢复率、首次正确但被改错的比例、操作支持率和追加查询延迟；目标漏检仍保留为失败。交互结果不与单轮核心结果混在一行。

## 5. 可选能力及范围控制

### 5.1 无目标时拒绝选择

示例：图中只有黑色包，查询“红色包”。补充人工确认确实无匹配实例的负查询，并保留有目标查询。低分可能意味着模型不理解或候选漏检，因此输出“未找到可靠匹配”，不据此断言原图没有该物体。

在开发集选择拒绝策略，可比较最高分、Top-1/Top-2 间隔或另训匹配分类器。空候选、单候选时的规则必须定义；这些分数不是天然校准概率。冻结策略后报告无目标误接受率、有目标误拒绝率及准确率与接受比例的关系。拒绝实验单独汇报；核心有目标任务中的拒绝仍按失败计分。

### 5.2 同一条件下的多目标

示例：“所有红色的包”。先限定同一组条件匹配多个实例，暂不覆盖任意“包和鞋”组合、人物关系或数量推理。

一条查询的标签改为完整目标 ID 集合，逐候选判断是否匹配；若训练，可使用多标签损失，不能继续用唯一目标 softmax 假设。选择阈值只在 dev 校准，避免通过 Top-k 暗中使用真实目标数量。

在固定一对一实例关联下报告集合 Precision/Recall/F1、集合完全正确率和掩码质量；重复预测计为多余输出，漏检目标计为遗漏。预先定义空集合计分，或将零目标明确排除并交由拒绝实验处理。该扩展需独立 schema/评估版本，不直接更改核心单目标接口。

### 5.3 掩码驱动的局部编辑

选中物体后，在其 mask 内改色，或保留目标而将背景变灰。首版采用确定性的像素处理，复用分割输出，无需增加生成式模型。

展示原图、选择、编辑结果和边界缺陷。像素处理版本检查作用范围外的像素保持不变；若使用羽化边缘，应记录实际允许改动区域。此检查验证编辑范围，不证明目标定位正确。编辑作为应用演示，不用观感替代 grounding 指标。

### 5.4 否定条件理解

示例：“没有条纹的上衣”“不是黑色的包”。先做小规模诊断，不承诺训练解决任意否定句。区分“确认属性不存在”和“图像看不清”；多个物体满足否定条件时，核心单目标集需补充唯一定位条件，或转入独立多目标集。

使用人工复核的肯定/否定查询组，报告准确率及成对正确率。不能假设图文预训练已解决否定，也不能只靠移除“不/没有”处理。若涉及额外模型或训练数据，作为独立方法登记。

## 6. 工作量与报告呈现

推荐依赖顺序：固定候选与 B1/B2 → X3 和语言分组评价 → 候选可视化 → 选择一项交互/可靠性扩展。研究数据整理可以与界面工作分开推进，负责人由团队确认；不预分配未经确认的成员任务或运行日期。

停止条件：扩展影响核心训练、测试隔离或报告时间时，保留已有可复现结果，停止增加功能。复杂人物关系、开放域对话、任意多目标组合和生成式试衣均不进入当前扩展承诺。

报告在 Technical Approach 写实际选定的方法，在 Results 写真实测得结果，在 Discussion/Limitations 写未实现项和失败原因。演示能力、运行实验、预期收益分别标明；不把本文规划当作完成证据。

## 7. 研究参考

- [Winoground: Probing Vision and Language Models for Visio-Linguistic Compositionality](https://arxiv.org/abs/2204.03162)：参考其组合语义评估思路；本文的服饰查询组是项目自建测试，不冒称官方 Winoground 结果。
- [Vision-Language Models Do Not Understand Negation / NegBench](https://arxiv.org/abs/2501.09425)：说明否定理解值得单独检验；论文结果不能直接充当本项目 SigLIP 2 配置的实验结论。
